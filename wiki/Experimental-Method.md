# Public experimental method

The operator describes a **partially AI-assisted workflow**. The complete private orchestration process is not disclosed, and the project does not claim to have executed a fully autonomous closed-loop optimizer.

## Research loop

1. **Stabilize the apparatus:** source version, native toolchain, hardware, test runner, corpus IDs, output schemas and audit logs.
2. **Construct the pattern library:** represent candidate optimization mechanisms as documented, revisable hypotheses.
3. **Compose explicit experiments:** generate named configurations and compile each candidate with its prescribed flags.
4. **Validate before timing:** run compilation and basic correctness gates; exclude invalid candidates from performance ranking.
5. **Explore broadly:** include varied JSON structures and retain surprising negative or positive results.
6. **Analyze against evidence:** use AI-assisted reports as working memory but check statements against measured records.
7. **Confirm separately:** freeze hypotheses and use independent/held-out corpora or another compiler or RISC-V system.

## Human responsibility

The human operator sets scope, experimental budgets and acceptance criteria, approves remote launches, reviews claims, handles attribution, and decides what is ready to publish. Generated code or reports are not treated as authoritative solely because a model produced them.

## Precise implementation boundaries

The publicly documented E00–E14 configurations were **fixed hypotheses selected for manual campaigns**. AI assistance in developing that library does not mean all configurations were created or chosen dynamically during testing. The recorded experiments did **not** automatically train a routing policy from the observed measurements.

The historical results use hardware-specific native execution, not general-purpose proof that this development approach is more productive than conventional engineering.
