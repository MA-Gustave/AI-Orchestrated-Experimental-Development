# Annotated academic references

These are research starting points, **not** quotations of their authors or evidence that the project's novel claims are already established. The final submission should verify edition, publisher metadata, author lists and citation style. All linked literature may be read independently of the RVV-VLA case study.

## A. Philosophy and hierarchical organization

**Aristotle.** *Metaphysics* VII–IX, especially IX.8 on actuality and potentiality; *De Anima* II.1. Philosophical analogies for form, matter and organized wholes. Use book-and-section references; choose and cite a scholarly edition/translation before publication. [W. D. Ross translation, Internet Classics Archive](https://classics.mit.edu/Aristotle/metaphysics.html). Aristotle did not formulate a computer-automation theory.

**Stanford Encyclopedia of Philosophy (revised 2024).** [Form vs. Matter](https://plato.stanford.edu/entries/form-matter/). Useful secondary analysis of Aristotle's relative matter and nested material compositions, along with disputed interpretations of prime matter.

**Simon, Herbert A. (1962).** “The Architecture of Complexity.” *Proceedings of the American Philosophical Society* 106(6), 467–482. [JSTOR](https://www.jstor.org/stable/985254). Modern argument for hierarchical, nearly decomposable systems, a much closer systems-science predecessor for modular abstraction.

## B. Human–computer collaboration and automation

**Licklider, J. C. R. (1960).** “Man-Computer Symbiosis.” *IRE Transactions on Human Factors in Electronics* HFE-1(1), 4–11. [DOI: 10.1109/THFE2.1960.4503259](https://doi.org/10.1109/THFE2.1960.4503259). A fundamental precursor to human-directed goal setting and machine-supported operations.

**Engelbart, Douglas C. (1962).** *Augmenting Human Intellect: A Conceptual Framework.* Stanford Research Institute report. [Report](https://dougengelbart.org/pubs/augment-3906-Framework.html). Tools, language, techniques and people can be designed together as augmenting systems.

**Bainbridge, Lisanne (1983).** “Ironies of Automation.” *Automatica* 19(6), 775–779. [DOI](https://doi.org/10.1016/0005-1098(83)90046-8). Essential counterpoint: automating routine work can leave humans with particularly difficult supervisory decisions.

**Brooks, Frederick P. (1987).** “No Silver Bullet—Essence and Accidents of Software Engineering.” *Computer* 20(4), 10–19. [DOI](https://doi.org/10.1109/MC.1987.1663532). Abstraction can alleviate aspects of tool-related complexity without removing essential problem complexity.

**Parasuraman, Raja; Sheridan, Thomas B.; Wickens, Christopher D. (2000).** “A Model for Types and Levels of Human Interaction with Automation.” *IEEE Transactions on Systems, Man, and Cybernetics Part A* 30(3), 286–297. [DOI](https://doi.org/10.1109/3468.844354). A functional taxonomy for which activities remain human-controlled.

## C. Automation of software work

**Schmidt, Douglas C. (2006).** “Model-Driven Engineering.” *Computer* 39(2), 25–31. [DOI](https://doi.org/10.1109/MC.2006.58). Model-to-implementation transformation is an earlier example of automating a level of translation.

**Lieberman, Henry; Paternò, Fabio; Wulf, Volker (eds., 2006).** *End User Development.* Springer. [DOI](https://doi.org/10.1007/1-4020-5386-X). Direct background for tools enabling people without extensive programming training to modify or construct systems.

**Gulwani, Sumit; Polozov, Oleksandr; Singh, Rishabh (2017).** “Program Synthesis.” *Foundations and Trends in Programming Languages* 4(1–2), 1–119. [DOI](https://doi.org/10.1561/2500000010). Automated generation of programs constrained by specifications and examples.

## D. Algorithm selection, empirical tuning and coding agents

**Rice, John R. (1976).** “The Algorithm Selection Problem.” *Advances in Computers* 15, 65–118. [DOI](https://doi.org/10.1016/S0065-2458(08)60520-3). Foundational literature for choosing an algorithm from instance-specific characteristics; relevant to JSON workload profiles.

**Ansel, Jason et al. (2014).** “OpenTuner: An Extensible Framework for Program Autotuning.” *PACT 2014*. [DOI](https://doi.org/10.1145/2628071.2628092). Prior art for systematic empirical exploration of program configurations.

**Qian, Chen et al. (2024).** “ChatDev: Communicative Agents for Software Development.” *ACL 2024*. [ACL Anthology](https://aclanthology.org/2024.acl-long.810/), [DOI](https://doi.org/10.18653/v1/2024.acl-long.810). Example of communicating development-agent roles and multi-stage artifact generation.

**Romera-Paredes, Bernardino et al. (2024).** “Mathematical Discoveries from Program Search with Large Language Models.” *Nature* 625, 468–475. [DOI](https://doi.org/10.1038/s41586-023-06924-6). FunSearch links model-generated programs to executable evaluation. Published online in 2023 and in a 2024 journal volume.

**Novikov, Alexander et al. (2025).** “AlphaEvolve: A Coding Agent for Scientific and Algorithmic Discovery.” [arXiv:2506.13131](https://arxiv.org/abs/2506.13131). Treat as a technical preprint unless a later venue version is verified; a close precedent for proposing and testing algorithmic code variants.

## E. Technical standards and case-study primary sources

**Bray, Tim (2017).** *The JavaScript Object Notation (JSON) Data Interchange Format*, RFC 8259. [RFC Editor](https://www.rfc-editor.org/info/rfc8259/). JSON syntax and interoperability; no universal performance-profile field is defined.

**MA-Gustave (2026).** [RVV-VLA-Lab](https://github.com/MA-Gustave/RVV-VLA-Lab) and [Simdjson-rvv-vla](https://github.com/MA-Gustave/Simdjson-rvv-vla). Primary project source and measurements, **not independent peer-reviewed confirmation**. A publication should freeze version SHA, access date and software archive IDs when available.

**simdjson contributors.** [Official simdjson repository](https://github.com/simdjson/simdjson). Source project that the RVV-VLA experiments build upon. Respect existing software attributions and source licences.

## Evidence hierarchy

Peer-reviewed sources support prior research; editions of philosophical primary texts support historical interpretation; raw benchmark files and exact builds support quantitative experimental claims; preprints require status labels; this project's documentation supports statements about *the project itself*, not independent validation.
